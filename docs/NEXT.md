## Решено, делаем после анализа статистики
- План хранения под 10 ГБ (см. `research/bohemia-api-observations.md`, раздел «План хранения»).
- **Свёртки нагрузки (решено: 10 минут):** `server_load_10m` для отслеживаемых (avg/min/max онлайн, avg/max очередь, входы/выходы, samples),
  `server_load_daily` для всех серверов из сканов, `poll_stats_daily`. Фоновая задача раз в час, идемпотентно; поминутные снимки — 7 дней.
  График любого дня за год назад: 144 точки для отслеживаемых, 1 точка/день для остальных. Статистика от raw не зависит.
- Оптимизация опроса: `listPlayers` по сохранённому roomId, `rooms/search` раз в N минут и при `ROOM_NOT_FOUND`.
- Исключать запароленные комнаты из выборки (после того, как узнаем поле фильтра).

## Проверенные гипотезы
- **Позиция в очереди — опровергнуто 2026-09-11.** Порядок `queuePlayers[]` не связан с очерёдностью (см. research). События с номером в очереди из lobby API невозможны; остаются `PLAYER_ENTERED_QUEUE` / `PLAYER_LEFT_QUEUE` с длительностью ожидания и итогом.
- **Идентичность сервера:** roomId переживает переезд адреса (129 случаев/сутки), меняется при рестарте (18). Резолюция ROOM_ID → HOST_ADDRESS, автослияние дублей — реализовано, ждёт деплоя.
