# ADR 0003 — PostgreSQL как единое хранилище

**Статус:** Proposed · **Дата:** 2026-09-07

## Контекст

Проект создаётся с нуля, внешних ограничений по БД нет (AGENTS.md §21). Нужны: история с интервалами неопределённости, JSON raw payload с retention, оконные функции для аналитики co-presence.

## Решение

- PostgreSQL 16+. Одна БД, одна схема, таблицы группируются префиксом владельца-модуля неявно (через миграции модуля), без отдельных схем на старте.
- Доступ через `pgx/v5`, рукописный SQL в репозиториях. Транзакция на один poll-цикл сервера: observation + diff + sessions + outbox записываются атомарно.
- Время везде `timestamptz` в UTC.
- Внутренний PK — `bigint generated always as identity`. Внешние ID (`bohemia_user_id`, `room_id`, `host_address`) — атрибуты с индексами (AGENTS.md §25.3).
- Raw payload — `jsonb` в отдельной таблице `raw_payload` с `expires_at`; чистка фоновой задачей, retention конфигурируемый (по умолчанию 14 дней).
- Никаких `ON DELETE CASCADE` на исторические таблицы. Историю не удаляем, только помечаем.

## Последствия

- Простая локальная разработка: `docker compose` с Postgres.
- Аналитика на первом этапе — SQL с оконными функциями, без отдельного OLAP.
- Если объём `server_observation` вырастет — партиционирование по `observed_at`, решение отложено.
