# Телеграм-бот: команды и поведение

Бот живёт в отдельном проекте (`teamspeakbot`) и работает только через REST observer'а (`docs/api.md`).
Observer не знает про Telegram; бот не знает про Bohemia.

Бот хранит у себя:

| Сущность | Поля |
|---|---|
| подписка | `chat_id`, `player_id`, опционально `server_id`, `created_at` |
| курсор ленты | один на бота: `last_event_id` |
| кеш имён | `player_id → последний ник`, `server_id → имя` (для текстов, не обязателен) |

Ник в подписке **не хранится**: подписка на `player_id`, а ник в событиях приходит актуальный.

## Цикл опроса (бот тянет сам)

1. Первый запуск: `GET /events/head` → сохранить `head` как `last_event_id`. Всё, что было раньше, не рассылается.
2. Каждые 10–20 секунд: `GET /events?after=<last_event_id>&player_ids=<все player_id из подписок>&limit=500`.
3. Для каждого события найти подписки на `event.player_id`; если у подписки задан `server_id`, сравнить с `event.server_id`.
4. Отправить сообщения, затем сохранить `next_after` из ответа как новый `last_event_id`. Порядок важен:
   сохранять курсор **после** успешной отправки, иначе при падении события потеряются.
5. Запрашивать и при нуле подписок: курсор должен двигаться, иначе после первой подписки прилетит история.
6. Если `player_ids` пустой — не передавать параметр вовсе (иначе фильтр вернёт всё).

Задержка уведомления: до 20 секунд опроса плюс интервал наблюдения (сейчас 2 минуты). Мгновенных уведомлений
быть не может: сам факт входа observer видит при следующем опросе сервера.

## Команды

### `/watch <ник или id>` — подписаться

- Аргумент только из цифр → считаем `player_id`, проверяем `GET /players/{id}`.
- Иначе `GET /players?nick=<аргумент>`:
  - **0 совпадений** → «Игрок не найден. Возможно, он не заходил на отслеживаемые серверы. Список серверов: /servers».
  - **1 совпадение** → подписать, ответить карточкой (см. шаблон ниже).
  - **несколько** → инлайн-кнопки выбора: по кнопке на игрока, в подписи `current_nickname`, где сейчас или последний
    сервер, платформа, когда видели. Callback-данные — `player_id`.
- Повторная подписка — ответить «уже отслеживается».

### `/unwatch <ник или id>` — отписаться

Тот же разбор аргумента; при нескольких подписках с похожими никами — выбор кнопками из **своих** подписок.

### `/list` — мои подписки со статусом

Один запрос `GET /players?ids=<все player_id подписок>`. Онлайн-игроки идут первыми.

```
Ваши подписки (4):

🟢 Salat Majompski — [RU] #1 | ARMA-RUSSIAN.RU, 1 ч 12 мин
🟢 Bengalthe3rd — [EU] LuckyGames Hardcore, 8 мин
⚪ Asariss — офлайн, был 3 ч назад на [OG9] Old Guys 9
⚪ ЧЕГЕВАРА — офлайн, был 2 дн назад на [PL] POLSKA GUROM
```

Онлайн определяется полем `online`: не `null` — игрок на сервере, `online.since` — с какого момента.
Офлайн: `last_seen_at` и `last_server`.

### `/where <ник или id>` — где сейчас

`GET /players/{id}` или поиск по нику. Ответ: либо «на сервере X уже 40 мин», либо «офлайн, последний раз
видели N назад на сервере Y». Подписки не требует.

### `/who <ник>` — карточка игрока

`GET /players?nick=`. Показать: текущий ник, все известные ники, платформы, когда первый и последний раз видели,
число визитов, где сейчас. Кнопки «Подписаться» и «История».

### `/history <ник или id>` — последние визиты

`GET /players/{id}/sessions?limit=10`:

```
Salat Majompski — последние визиты:

11.09 21:03 – 22:15 (1 ч 12 мин) — [RU] #1 | ARMA-RUSSIAN.RU (сейчас там)
11.09 19:40 – 20:55 (1 ч 15 мин) — [OG9] Old Guys 9, ник «Salat»
10.09 23:10 – 01:40 (2 ч 30 мин) — [RU] #1 | ARMA-RUSSIAN.RU
```

Ник визита берётся из `session.nickname` — показывать его, если отличается от текущего.
`status = CLOSED_DATA_GAP` помечать как «данные прерывались», иначе длительность выглядит недостоверной.

### `/server <подстрока>` — сервер

`GET /servers?name=<подстрока>`. Онлайн, лимит, очередь, отслеживается ли, когда снимок.
Если не отслеживается — предупредить: «события игроков с него не собираются».

### `/servers` — отслеживаемые серверы

`GET /servers?tracked=true`, вывести топ по онлайну, всего N. По серверу — онлайн/лимит и очередь.

### `/help` — список команд.

### `/status` — здоровье наблюдения (только для админов бота)

`GET /observation-status`: время последнего скана лобби, число отслеживаемых серверов, известных игроков,
открытых сессий, разбивка опросов за час по статусам. Если у части серверов `data_age_seconds` большой —
показать их: значит по этим серверам события задерживаются.

## Шаблоны уведомлений

Из ленты приходят события; тексты формирует бот.

| `type` | Сообщение |
|---|---|
| `PLAYER_JOINED_SERVER` | 🟢 **Salat Majompski** зашёл на **[RU] #1 \| ARMA-RUSSIAN.RU** в 21:03 |
| `PLAYER_LEFT_SERVER` | ⚪ **Salat Majompski** вышел с **[RU] #1 \| ARMA-RUSSIAN.RU** в 22:15, провёл 1 ч 12 мин |
| `PLAYER_ENTERED_QUEUE` | 🕒 **Salat Majompski** встал в очередь на **[OG9] Old Guys 9** |
| `PLAYER_LEFT_QUEUE`, `payload.result = JOINED_SERVER` | 🟢 **Salat Majompski** вошёл на **[OG9] Old Guys 9** после 10 мин в очереди |
| `PLAYER_LEFT_QUEUE`, `payload.result = LEFT_QUEUE` | ⚪ **Salat Majompski** ушёл из очереди **[OG9] Old Guys 9**, прождав 8 мин |
| `PLAYER_NICKNAME_CHANGED` | ✏️ **Salat Majompski** теперь **Salat** |

Правила:
- `duration_seconds` и `payload.waited_seconds` форматировать по-человечески: «8 мин», «1 ч 12 мин», «2 дн».
- `after_data_gap = true` → добавить «(данные прерывались, время приблизительное)».
- События с `startup_replay` в ленту не приходят (если не передан `include_replay=true`) — рассылать их нельзя.
- Время события — `occurred_at` в UTC, переводить в таймзону чата.
- Смена ника приходит с привязкой к серверу, где замечена; в тексте сервер не обязателен.
- Пачка событий одного игрока за один опрос (вышел с A, зашёл на B) — склеивать в одно сообщение:
  «перешёл с A на B». Определять по событиям одной страницы с одним `player_id`.

## Ограничения, о которых бот должен предупреждать

- Видны только игроки на **отслеживаемых** серверах (`GET /servers?tracked=true`, сейчас ~107 из ~5050).
  Игрока с неотслеживаемого сервера бот не найдёт и не увидит.
- Комнаты с паролем список игроков не отдают вовсе.
- Точность времени выхода — интервал опроса: реальный выход между предыдущим опросом и `occurred_at`.
- Ники не уникальны: подписка всегда на `player_id`, в выборе показывать различающие признаки.
